## Full training pipeline (`make train`)

Training each agent from scratch, from random weights, until convergence.

### Summary table

| Environment | Agent | Episodes | Converged | Final success | Notes |
|---|---|---|---|---|---|
| GridWorld | Tabular Q | 1000 | ep 101 | 100% | Target at (4,4), random start |
| FrozenLake | Tabular Q | 2000 | ep ~391 | 97% | Fixed map per instance, stochastic slip |
| PredatorGrid | Tabular Q | 3000 | ep ~484 | 96% | Greedy predator, 4 corner pairings |
| MazeWorld | DQN | 3000 | ep ~883 | 91% | New random maze every episode |
| ResourceHunter | DQN | 5000 | ep ~4000 | converges | epsilon_decay=0.999 |

### What the curves tell you

**GridWorld** converges at episode 101 — that's the minimum. The epsilon schedule needs ~100 episodes to decay from 1.0 to a useful exploitation range. At that point, the Q-table has seen every (state, action) pair and the policy is optimal. The reward curve shows a clean step function: flat near zero, then jumps to positive as the agent starts exploiting.

**FrozenLake** has a noisier convergence curve than GridWorld because the stochastic slip creates variance even in the optimal policy. A perfect policy on FrozenLake is not 100% success — holes are sometimes unavoidable if you slip at the wrong moment. The 97% ceiling is the theoretical near-optimum.

**PredatorGrid** takes more episodes than FrozenLake even though it's deterministic. The reason is the Q-table's state space: 6 values (agent + target + predator positions) vs. 5 (agent + target + tile). More states = more exploration required. The predator also forces the agent into suboptimal paths that accumulate negative transitions before the Q-table learns to avoid them. The "caught rate" visible in the outcome subplot drops as training progresses.

**MazeWorld** has the most interesting curve: a slow climb from ~30% to ~90% over 3000 episodes. Early in training (episodes 1-500), the DQN is learning what walls look like in the 53D state and that bumping them costs -0.5. Episodes 500-1500 show the network starting to navigate corridors. The last 1000 episodes are policy refinement — the network has learned general maze navigation and is optimizing path efficiency.

The generalization metric: success rate in episodes 1-200 vs. last 200 episodes shows a large jump. The DQN isn't memorizing specific mazes — it can't, since each episode is a new one. The curve's rise is genuine generalization.

**ResourceHunter** has the slowest, noisiest convergence. The reward signal is sparse early (the agent starves before collecting anything), and the potential-based shaping reward (`+0.05 × dist_improvement`) gives some gradient but not enough to pull the agent toward a full sequence. The epsilon_decay=0.999 is critical: with 0.997, the agent commits to exploitation too early, before seeing enough collection sequences to learn the multi-target policy.

## Transfer learning benchmark (`make benchmark`)

Metric: number of episodes to reach 75% success rate over a rolling window of 100 episodes. Max per environment shown in parentheses.

### Results table

| Environment | Scratch | Transfer | Gain | Frozen layers |
|---|---|---|---|---|
| GridWorld | 101 | 101 | 0 | input + hidden |
| FrozenLake | 681 | 904 | -223 | input + hidden |
| PredatorGrid | 578 | 699 | -121 | input + hidden |
| **MazeWorld** | **811** | **101** | **+710** | input + hidden |
| ResourceHunter | >2500 | >2500 | 0 | input + hidden |

### MazeWorld (+710)

The most dramatic result. The scratch agent takes 811 episodes to reach 75% success. The transfer agent reaches it at episode 101 — the same episode that scratch GridWorld converges.

The learning curve shape is different too: scratch MazeWorld shows the characteristic slow climb, building features from noise. Transfer MazeWorld shows a much steeper early ramp — the feature extractor is already competent from day one, so the output layer converges as soon as it has enough transitions to fit.

**What the variance tells you:** Transfer MazeWorld has lower variance in its learning curve than scratch MazeWorld. With frozen base layers, the only source of training noise is the output layer's gradient updates (64→4 weights). Scratch has noise from all three layers simultaneously, including the unstable early phase where the network is fitting random features.

### FrozenLake (-223)

Transfer is measurably slower, not just slightly worse. The learning curve shows the transfer agent making slower early progress — its frozen input layer is encoding features tuned to a different FrozenLake instance. The output layer receives misleading signals and must first "unlearn" the wrong feature weighting before it can make progress.

This shows up as a longer flat region at the beginning of the transfer curve, followed by a convergence rate similar to scratch (once the output layer has seen enough transitions to override the wrong features). Scratch doesn't have the flat region — it starts from neutral.

### PredatorGrid (-121)

Same dynamic as FrozenLake, smaller magnitude. The 6D state is simpler than FrozenLake's 5D (both have 4 action dimensions, but PredatorGrid's positions are more directly readable), and the frozen input layer is less harmful because there's less layout-specific information to misencoder.

### GridWorld (0)

Two agents, identical convergence. The loaded checkpoint (`gridworld.pth`, state_size=4 matches) transfers both input and hidden layers. But GridWorld is so simple that 101 episodes is the minimum possible convergence time, not a bottleneck. Even a perfect feature extractor can't make the epsilon schedule decay faster.

### ResourceHunter (0)

Neither agent converges in 2500 episodes. The full pipeline uses 5000 episodes with epsilon_decay=0.999, which means epsilon reaches its minimum around episode 3000 — giving 2000 episodes of real exploitation. The benchmark caps at 2500 total, which is not enough for either approach.

The pretrained `resource_hunter.pth` reflects a partially trained agent (0% success in the pretrain session). Loading those weights provides no useful initialization — and the benchmark confirms it.

## What these results imply for next steps

**Transfer learning is real, but conditional.** The MazeWorld result is not a fluke — it's reproducible and mechanistically explained. The hidden_layer (128→64) is genuinely learning distribution-general navigation features after sequential pretraining.

**The fixed-map problem is solvable.** FrozenLake and PredatorGrid give negative results because their input_layer encodes instance-specific geometry. Progressive freezing (training input_layer, freezing only hidden_layer) would likely turn those results positive. The 128→64 features should transfer even when 4D/5D/6D→128 doesn't.

**ResourceHunter needs more pretraining budget.** The simplest fix: increase pretrain episodes to 6000 and benchmark to 4000. The hard version: add curriculum scheduling that allocates more time to harder environments.

**Larger environments are the next frontier.** All five environments here are toy-scale (5×5 or 7×7). The interesting question is whether the same transfer mechanism works on larger state spaces — a 15×15 MazeWorld, or a version with partial observability (fog of war). The architecture scales: just change `state_size` and the network adapts. The open question is whether 2 hidden layers are enough or whether deeper networks are needed for feature generalization at scale.

**Real games.** The environments are abstract. The same DQN + transfer architecture could be applied to Atari frames (via a CNN rather than a linear encoder), robot navigation in continuous state spaces, or multi-agent scenarios. The core insight — that a universal feature extractor trained on diverse environments transfers better than one trained on a single task — is not specific to these five environments.
